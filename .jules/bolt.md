## 2024-07-09 - Filter Before Sorting in LibraryViewModel
**Learning:** Found a classic performance bottleneck where `items` are sorted first (O(N log N)) and then filtered by `searchText` (O(N)). When users type in a search box, doing this on every keystroke for large folders (like a root folder with hundreds/thousands of archives) can cause main thread hitching.
**Action:** Filter the array first based on `searchText`, and only apply the expensive sort (`localizedStandardCompare`) on the resulting subset. This reduces the time complexity to O(N) + O(K log K) where K is the number of matched items, providing a measurable UI responsiveness boost when searching.
## 2024-08-01 - Avoid dynamic .regularExpression compilation in Swift View/Model logic
**Learning:** In Swift, using `.range(of:options: .regularExpression)` or `.replacingOccurrences(of:with:options: [.regularExpression])` dynamically compiles the NSRegularExpression every time it's called. When used in list models (`DriveItem`), view models (`LibraryViewModel`), or views (`ReaderView`), this can easily cause main thread hitches when iterating over thousands of items or re-evaluating views.
**Action:** Use precompiled static `NSRegularExpression` instances with `.firstMatch` or `.stringByReplacingMatches` initialized using `try! NSRegularExpression(pattern:)` to completely eliminate regex compilation overhead in the runtime logic path.
