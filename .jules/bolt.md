## 2024-07-09 - Filter Before Sorting in LibraryViewModel
**Learning:** Found a classic performance bottleneck where `items` are sorted first (O(N log N)) and then filtered by `searchText` (O(N)). When users type in a search box, doing this on every keystroke for large folders (like a root folder with hundreds/thousands of archives) can cause main thread hitching.
**Action:** Filter the array first based on `searchText`, and only apply the expensive sort (`localizedStandardCompare`) on the resulting subset. This reduces the time complexity to O(N) + O(K log K) where K is the number of matched items, providing a measurable UI responsiveness boost when searching.
## 2024-07-28 - Precompile Regexes in Swift Models and ViewModels
**Learning:** Found performance bottlenecks where regular expressions were compiled dynamically within initialization loops or methods called frequently (`DriveItem.init(parsing:)` and `LibraryViewModel.extractSeriesTitle(from:)`). Using `.range(of: ..., options: .regularExpression)` blocks the main thread in these scenarios.
**Action:** Precompile regexes as static `NSRegularExpression` properties using Immediately Invoked Function Expressions (IIFEs) with `do-catch` blocks and `fatalError()`. Safely map `NSRange` to Swift `Range` using `NSRange(string.startIndex..<string.endIndex, in: string)` to avoid index offset issues, which significantly reduces overhead.
