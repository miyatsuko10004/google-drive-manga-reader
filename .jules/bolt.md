## 2024-07-09 - Filter Before Sorting in LibraryViewModel
**Learning:** Found a classic performance bottleneck where `items` are sorted first (O(N log N)) and then filtered by `searchText` (O(N)). When users type in a search box, doing this on every keystroke for large folders (like a root folder with hundreds/thousands of archives) can cause main thread hitching.
**Action:** Filter the array first based on `searchText`, and only apply the expensive sort (`localizedStandardCompare`) on the resulting subset. This reduces the time complexity to O(N) + O(K log K) where K is the number of matched items, providing a measurable UI responsiveness boost when searching.
## 2024-07-26 - Prevent Dynamic Regex Compilation in Views and ViewModels
**Learning:** Using `String.range(of:options: .regularExpression)` or `replacingOccurrences(of:options: [.regularExpression])` forces dynamic compilation of the regular expression string on every execution. In computationally intensive operations, such as mapping over hundreds of `DriveItem` instances to populate a Library view or parsing volume info for suggestions, this can block the main thread.
**Action:** Always precompile regular expressions statically as `static let regex = try! NSRegularExpression(pattern: "...")` within the ViewModel/Model and use the methods like `firstMatch` or `stringByReplacingMatches` instead. Use `NSRange(string.startIndex..<string.endIndex, in: string)` to safely map ranges between native Swift `String` and `NSRegularExpression`.
